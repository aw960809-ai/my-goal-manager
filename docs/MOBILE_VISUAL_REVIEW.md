# 第三階段｜手機實際畫面審查（第二批）

這一批根據 2026-10-08 的手機截圖，重新整理**同一份** `css/design-system.css` 的第三階段區塊，並刪除三條會蓋過新版密度變數的舊宣告，不新增覆蓋檔、不改動 HTML、資料層、PWA、統計或紀錄。

## 對照問題

| 問題 | 修改方法 | 驗收方式 |
|---|---|---|
| 首頁優先項目佔用過多高度 | 徽章與名稱排在同列，縮短卡片及 KPI 高度 | 手機 320～430px 無橫向溢出；徽章不覆蓋文字 |
| 獎學金標籤擠壓名稱 | 名稱使用完整寬度；適配標籤移至下方，保留原按鈕和操作 | 長標題完整可見；點擊仍開啟原資訊窗 |
| 獎學金資訊與篩選過於疏鬆 | 壓縮卡片間距、分類控制與統計概覽 | 不隱藏資格結果、截止日或來源 |
| 浮動設定齒輪遮住內容 | 手機改為相對 `.app` 定位的頂端按鈕，頁面捲動不跟隨 | 各主要頁標題不被齒輪遮住，設定功能保留 |
| 舒適／精簡模式覆蓋互相打架 | 讓手機 panel padding 共用 `--gm-layout-pad` 變數 | 切換密度時真正反映空間差異 |

## 與早上完整計畫的關係

本批只做第三階段的根本整理及兩張手機截圖反映的問題。活動雷達四格卡片合併篩選、行事曆的資訊結構重整、設定診斷入口整理分屬下一階段，不在本次偷偷修改程式邏輯。

## 安全界線

僅更新 `css/design-system.css`、增加 `tests/ui/design-system-mobile-review.test.js` 和本說明文件。符合已建立的低風險 UI 白名單，不讀取或改寫使用者資料。

在 `auto/ui-*` 分支執行 `bash scripts/verify.sh`；再經 GitHub PR 安全檢查，成功後才由安全工作流程自動合併並部署。新版位號仍為 V98.11.6，這批為 CSS-only 改版。
