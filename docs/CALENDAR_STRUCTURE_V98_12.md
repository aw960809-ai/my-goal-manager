# 行事曆結構改版 V98.12.0 — 一次完整模組驗收

## 已完成的操作契約
- **年檢視**：12 個月份，各有來源類型摘要；點選月份進入月檢視。
- **月檢視**：固定 42 格，但手機格內只顯示日期和分類小點；日期不因長活動名稱撐開。點日期會更新下面的當日清單。
- **日檢視**：只看某一天的完整日程。上一日／下一日導覽跨月與跨年也正確。
- **分類**：全部、東海校曆、已安排、子任務截止；切換篩選不更改資料。
- **來源**：`db.schoolCalendar`、尚未取消的 `db.calendarEvents`、Level 3 且未完成／未封存的截止日。活動雷達未加入行事曆者不視為已安排。
- **日期**：所有日期以本地曆日 `YYYY-MM-DD` 運算，避免把日期字串解讀為 UTC 午夜；包含月末、閏年及跨年測試。
- **查看與編輯**：原有手動新增、刪除、活動加入與取消流程保留。目標截止日只讀，點「查看目標」回到原功能。
- **近期 14 天**：只讀摘要，不增加額外通知或寫入行為。

## 安全邊界
- 不改動 schema：`GOAL_MANAGER_SCHEMA_VERSION=6`。
- 不改動 `data/*.json`、個人資料庫、localStorage/IndexedDB、歷史紀錄、活動推薦或獎學金。
- 不修改校曆來源內容；不將現有校曆誤說成即時官方同步。
- 檢視與篩選無儲存副作用；只有既有的使用者日期選擇及新增／取消功能會沿用原本的保存程序。
- 新增 scoped `css/calendar.css` 作為行事曆唯一最新設計層；其他模組外觀不動。
- PWA 升級至 V98.12.0，但資料 schema 保持 V6，會更新 cache namespace。

## 封版標準
1. `bash scripts/verify.sh` 全部通過，新增的日曆 domain / UI 回歸測試通過。
2. GitHub CI 通過、人工審查合併、GitHub Pages 完成正式部署。
3. 手機核對月曆、日期選取、日清單、年檢視、目標截止日、手動新增／取消活動。
4. 無資料遺失、計時器或既有統計異常，就凍結此模組。字級、留白等 P3 事項留待最後全站統一檢查。
