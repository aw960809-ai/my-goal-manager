# 活動雷達第三圈官方來源擴充：封版驗收標準

## 範圍與目的
只擴充苗栗、彰化、南投與雲林縣的**經核對官方頁面**；第三圈依原設計互斥於東海校內、臺中及全國。原有五個來源保持啟用。**本批不修改 UI、四層目標、計時、個人資料、推薦適配分數算法、來源封存算法或行事曆。**

## 技術保護

- 白名單固定 HTTPS 主機與官方活動明細路徑，不可任意追蹤第三方 URL。
- 每個來源最多檢查 7 個最新官方明細，網站失聯、細節結構改變、沒有可驗證官方活動連結均視作**來源失敗／保留舊資料**；不做推測填補。
- 日期必須來自活動行事曆欄位或明細的活動日期，民國年會正確轉換。發布／上版日期不能直接充當活動日期。
- 已額滿、取消、特定身分、沒有可核實未來活動日的項目不列入推薦；活動需經原有 `fit_candidate` 與身分資格判斷、語意去重、時效管理才可公開推薦。
- 當某來源沒有現階段符合資格與適配門檻的活動時，第三圈可以是 **0 項**；不得偽造或降低既有門檻。
- 原本五個來源、手動活動、個人資料與歷史紀錄都不做修改。原有 AutoFetch `reconcile_activity_catalog` 及備份、歸檔流程繼續負責來源失敗時保留紀錄。

## 交付驗收（一次完整模組）

1. Python 九項離線案例：四縣成功解析、民國／西元日期、惡意連結、來源斷線、過期與限定身分排除。
2. `scripts/verify.sh` 全面回歸及原有 `autofetch.py --self-test` 通過。
3. 合併前審查只看到新增四縣來源與測試／說明。任何受保護或不在範圍的修改必須停止。
4. 合併後 GitHub Actions 執行 AutoFetch，確認來源健康、個別失敗保留及四縣分別的接受／排除統計；至少兩個區域網站可讀，否則排查網站結構或聯網，**不得宣稱功能實際資料已上線**。
5. 手機上第三圈與來源更新狀態無重大問題，即將本模組凍結，進入行事曆重構。卡片間距和次要視覺事項統一留至最終精修。

資料來源可能隨官網設計變更，因此「官方入口可讀」不等於「目前一定有符合資格的活動」。禁止為了填滿第三圈而將未經驗證的公告視為活動。
